STATELENS 01 / 13
STATELENS

The observation compression layer for UI agents.

Computer-use agents waste money re-reading screenshots where nothing meaningful changed. StateLens turns screenshot streams into semantic state changes before the expensive model sees them.

Proof point — 81–90% cost reduction across two adversarial screenshot scenarios with 78–100% event-capture accuracy, measured with real Anthropic API usage. Now shipping as a drop-in Anthropic-compatible proxy — change one baseURL and your agent gets the savings with zero code changes.
screenshot stream → StateLens proxy → compact events → agent reasoning
Speaker note
Not another browser agent — the layer every browser or computer-use agent should call before spending vision tokens. The proxy form means no SDK swap, no MCP plumbing — just a different baseURL.
PROBLEM 02 / 13

The Problem

Agents are paying to rediscover the same screen.

screenshot→ vision model reasons→ action→ screenshot→ vision model reasons again

That loop is expensive because…

  • many consecutive screenshots are identical or nearly identical
  • small UI changes happen in one region, not the whole screen
  • text changes (errors, validation) can be extracted locally
  • raw screenshot reasoning leaves little persistent observability

The pain

Teams pay model prices for repeated visual context, then still have to debug what happened manually.

The waste isn't that vision is useless. The waste is using full vision as the default observation mechanism for every frame.

PRODUCT SURFACE 05 / 13

Product Surface

One pipeline. Four delivery surfaces. Led by a drop-in proxy.

Primary surface — Anthropic-compatible HTTP proxy

# Boot it
statelens proxy --port 18443

# Point any Anthropic SDK at it
export ANTHROPIC_BASE_URL=http://127.0.0.1:18443
# …that's it. No code changes. No tool calls. No prompts.

Proxy detects image blocks in POST /v1/messages, runs the pipeline on the latest screenshot, rewrites it to a compact text observation (or "no meaningful change" stub when the gate skips), and forwards upstream. Recursion guard via STATELENS_INTERNAL_ANTHROPIC_BASE_URL keeps internal Haiku calls from looping back.

action_failed is a first-class event

When the agent passes an actionLabel it expected to mutate the UI and the screen does not change, StateLens emits: 

{
  "changed": false,
  "keyframe": true,
  "event_type": "action_failed",
  "event_summary":
    "Action \"click_submit\" produced no
     meaningful UI change; the action may
     have failed or the page may be stuck",
  "vlm_called": false
}

No OCR, no VLM, no false-positive no_change hiding a stuck page.

Real-Time Agent Integration

The proxy beats middleware beats a prompt.

1
weakest

Policy prompt — voluntary

"Please call statelens_observe before reasoning." The agent has to choose. Easy to forget, easy to ignore.

2

Middleware — code-enforced, in-process

const { observation, route } = await captureAndRoute(page, {
  sessionId: 'login_flow', actionLabel: 'click_submit',
});
if (route.route === 'skip_vision')          { /* zero tokens */ }
if (route.route === 'use_text_observation') await model({ text: route.context });
if (route.route === 'use_full_vision')      await model({ image: screenshot });
3
strongest

Proxy — data-path, zero code change

const client = new Anthropic({
  baseURL: 'http://127.0.0.1:18443',  // ← only line that changes
});
// Your existing agent loop, unchanged.
await client.messages.create({ model: 'claude-sonnet-4-6', messages: [...] });

Proxy inspects the latest image block, runs observe(), rewrites the request before it hits Anthropic. Agent never sees JSON observations, no tool defs injected, no cache churn. The harness's 80% savings translate directly to a real client here.

Folder demo proves the pipeline. Adapter proves it in real-time loops. Proxy is the shape that asks least of the agent author — and is where cost numbers reproduce in production.
THE LESSON 10 / 13

The Delivery-Surface Lesson

We shipped MCP, dogfooded it, found it was more expensive — then built the proxy.

The pipeline savings are real. But the delivery surface matters as much as the pipeline. We learned this by measuring our own MCP server end-to-end inside Claude Code.

Dogfood: MCP on a short Opus session

Two Claude Code sessions, identical 12-frame login prompt, identical model. Run A used Read, Run B swapped to statelens_observe.

MetricReadMCP
Total cost$0.66$0.84
Output tokens2.1k3.5k
Cache write45.3k65.5k
Cache read657.8k685.1k

+27% MORE EXPENSIVE

Diagnosis — three overheads, all MCP, none pipeline

  • Tool-call arg verbosity — screenshot_path, session_id > file_path
  • MCP tool defs cached every turn — 4 tools × ~400 tokens × 14 turns = ~22k extra cache reads
  • JSON responses churn cache — each observation is textually unique, forces writes

Modeled breakeven on Opus: ~30–50 frames. Below that, MCP overhead dominates per-frame savings.

The fix — proxy form, same pipeline, different surface

Surface12-frame login result
MCP, short Opus session+27% more expensive
Proxy, prev+curr per turn−31.3% · 100% lenient · 0 misses
Proxy, single-image per turn−59.4% cheaper
Speaker note
The honest story to remember. We shipped, measured, found the bad result, diagnosed (surface, not pipeline), and shipped the right surface. The reversal — same flow, same pipeline, +27% → −59% — is the most credible thing in the deck.

  • StateLens timeline attached to test reports
  • compact healer context for failures
  • screenshots forwarded only when route is use_full_vision
  • Stagehand adapter as a second target

The healer signal we already ship

The action_failed event is the first healer signal shipped: when the test agent clicks submit and the screen does not move, the timeline records the action that did nothing — not just a quiet no_change gap.

Positioning

Playwright snapshots already handle DOM-heavy tests efficiently. StateLens focuses on screenshot-heavy fallback — visual UI, canvas, charts, custom widgets, and healer loops.
