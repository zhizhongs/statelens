THE WHEN MOMENT 02 / 08

The "When" Moment

Turn 30 in a Claude Code conversation. The bug isn't fixed. You're out of context.

paste screenshot→ agent reads it→ try a fix→ paste another screenshot→ context window full · /clear

Why the conversation dies

  • each pasted screenshot is thousands of tokens the agent never gets back
  • screenshot #6 is usually 95% identical to screenshot #5 — same page, one new error line
  • the signal the agent actually needed was one string of text in one region
  • by the time you're out of room, the agent has forgotten the original symptom
  • same shape, scaled up, kills every long computer-use / browser-agent loop

Ask a cheaper question first

Did anything meaningful change since last frame?
  If no, send a one-line stub.
  If yes, where on the screen?
    If text changed, what text?
      Only if local signals are insufficient
      → call a small VLM on the crop.

Move observation from pixels to state transitions — so context fills up with what the agent can reason about, not what the camera saw.

This is where StateLens comes from — an evidence ladder, not text-only compression

THE LESSON 05 / 08

The Delivery-Surface Lesson

The MCP form helped the developer moment but hurt context. We measured it, then built the proxy.

MCP was the obvious first surface for the Claude-Code-conversation "when" — but tool definitions live inside the very context window we're trying to protect. The pipeline savings are real; the delivery surface has to live on the data path, not in the conversation.

Dogfood — MCP on a short Opus session

Two Claude Code sessions, identical 12-frame login prompt, identical model. Run A used Read, Run B swapped to statelens_observe.

MetricReadMCP
Total cost$0.66$0.84
Output tokens2.1k3.5k
Cache write45.3k65.5k
Cache read657.8k685.1k

+27% MORE EXPENSIVE

Diagnosis — three overheads, all MCP, none pipeline

  • Tool-call arg verbosity — screenshot_path, session_id > file_path
  • MCP tool defs cached every turn — 4 tools × ~400 tokens × 14 turns ≈ +22k cache reads
  • JSON responses churn cache — each observation is textually unique, forces writes

Modeled breakeven on Opus: ~30–50 frames. Below that, MCP overhead dominates per-frame savings.

The fix — proxy form, same pipeline, different surface

Surface · session shape12-frame login result
MCP · short Opus editor session+27% more expensive
Proxy · prev+curr per turn (eval parity)−31.3% · 100% lenient · 0 misses
Proxy · single-image per turn (computer-use loop shape)−59.4% cheaper

The proxy advantage grows with loop length — the longer the conversation or agentic session, the more the fixed-overhead-free design pays off. The "when context runs out" moment gets pushed further and further away.

Speaker note
The honest story: shipped, measured, found the bad result, diagnosed (surface, not pipeline), shipped the right surface. The reversal — same flow, +27% → −59% — is the most credible thing in the deck, and it directly answers "which form actually preserves context".

  • what changed?

  • did an action do nothing?
  • which frames actually needed vision?
  • where did the agent waste work?

action_failed is a first-class event

When the agent passes an actionLabel it expected to mutate the UI and the screen does not change, StateLens emits: 

{
  "changed": false,
  "keyframe": true,
  "event_type": "action_failed",
  "event_summary":
    "Action \"click_submit\" produced no
     meaningful UI change; the action may
     have failed or the page may be stuck",
  "vlm_called": false
}

No OCR, no VLM, no false-positive no_change hiding a stuck page. The first healer signal a test agent needs.

THE KILLER WEDGE 07 / 08

Where StateLens Is Indispensable

The same "when" — at agent scale.

A developer hits the context wall after maybe 30 screenshots. A computer-use or browser-test agent hits it after 30 seconds. Same shape, three orders of magnitude faster — and every frame pasted into the loop pushes the agent closer to forgetting the goal. The proxy's savings compound every turn the loop survives.
